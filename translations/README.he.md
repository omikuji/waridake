כלי ל‑macOS שמסדר חלונות ולא עושה דבר מלבד לחלק את המסך.

*Waridake* (割り竹) פירושו „חישוק במבוק שסוע”: חתך אחד נקי, וזהו.

**מה הוא עושה:**

1. מגדירים אזורים לכל מסך
2. מחזיקים **Shift בזמן גרירת חלון** והאזורים מופיעים
3. משחררים מעל אזור והחלון מתיישב בו

בלי סבכי קיצורי מקלדת, בלי היסטוריית חלונות, בלי מנויים. הוא יושב בשורת התפריטים.

> הקובץ הקובע הוא [README.md](../README.md) באנגלית. אם התרגום הזה מפגר אחריו, האנגלי גובר.

## התקנה

דרושים כלי שורת הפקודה של Xcode (`xcode-select --install`).

```bash
git clone https://github.com/omikuji/waridake.git
cd waridake
make install   # → /Applications/Waridake.app
```

בהפעלה הראשונה macOS מבקש הרשאת נגישות. יש להפעיל את Waridake תחת **הגדרות המערכת ←
פרטיות ואבטחה ← נגישות**. אפשר לאשר גם כשהיישום פועל: הוא מבחין בכך תוך שנייה, ואין צורך
להפעיל מחדש.

כדי שייפתח בהתחברות: הגדרות המערכת ← כללי ← פריטי כניסה.

### הערה לגבי בנייה מחדש

החתימה היא ad hoc כברירת מחדל, ולכן **היא משתנה בכל בנייה ו‑macOS מסיר את ההרשאה בשקט** —
התיבה נשארת מסומנת אבל שום דבר לא עובד. אפשר להסיר את Waridake מרשימת הנגישות ולהוסיף שוב,
או לפתור את זה סופית: ליצור אישור חתימת קוד בחתימה עצמית (גישה לצרור מפתחות ← עוזר האישורים ←
צור אישור, סוג: חתימת קוד) ולבנות איתו:

```bash
make install SIGN_IDENTITY="Waridake Dev"
```

## שימוש

הכול נמצא מתחת לסמל שבשורת התפריטים.

| פריט בתפריט | מה הוא עושה |
| --- | --- |
| **סידור החלונות הפתוחים** | מכניס כל חלון פתוח לאזור הקרוב אליו ביותר. לסידור אחרי שחלונות זזו |
| **עריכת פריסה…** | העורך הגרפי, המתואר להלן |
| **פריסות…** | פריסות לפי מסך עם מועד השימוש האחרון, וגם ההיסטוריה |
| **עריכה כ‑JSON…** | קובץ ההגדרות בחלון עריכה פשוט |
| **טעינת הפריסה מחדש** | קורא את הקובץ שוב אחרי עריכה במקום אחר |

הפריסות נשמרות **לכל מסך בנפרד**, כי מסכים נבדלים בצורה ובגודל וחלוקה אחת אף פעם לא מתאימה
לכולם. מסכים מזוהים לפי ה‑UUID שלהם, ולכן ההגדרות שורדות ניתוק והפעלה מחדש.

### העורך הגרפי

**עריכת פריסה…** פותח עורך על כל המסכים המחוברים בבת אחת. מעצבים כל מסך בנפרד; לחיצה על
שמירה באחד מהם שומרת את כולם. הגדלים מוצגים באחוזים, כך שאין צורך לקרוא שברים.

| פעולה | מה היא עושה |
| --- | --- |
| **לחיצה ימנית על אזור** | חלוקה ל‑2 או 3, חלוקה שווה, מרכוז במסך |
| **הכפתור „מיזוג” שעל גבול** | מאחד את שני האזורים. מופיע היכן שהם יוצרים יחד מלבן |
| גרירת גבול | מזיזה אותו. האזורים משני הצדדים נמתחים איתו, כך שלא נפערים חורים |
| גרירת גבול **עם ⌥** | מזיזה גם את הגבול המשוקף, סימטרית סביב מרכז המסך — להרחבת אזור מרכזי באופן אחיד |
| לחיצה כפולה על אזור | חותכת אותו שם, לאורך הצלע הארוכה (⌥ הופך את הכיוון) |
| `V` `H` `⌫` `⌘Z` `R` | חלוקה, חלוקה לכיוון השני, מיזוג עם שכן, ביטול, חזרה להתחלה |
| `return` / `esc` | שמירה וסגירה / ויתור |

„חלוקה שווה של העמודה” משווה בין האזורים הערוכים זה מעל זה באותה עמודה (למשל ארבעה לאורך
השוליים השמאליים); בשורה מדובר ברוחב. אזורים באותו גודל במקום אחר במסך נותרים כשהיו.

„מרכוז במסך” מזיז אזור כך שיישב סימטרית סביב קו האמצע, בלי לשנות את גודלו. אזור הנוגע בשולי
המסך אינו יכול לזוז כך, ופריט התפריט נשאר מנוטרל.

הגבולות נצמדים לשולי אזורים אחרים ולערכים 1/4, 1/3, 1/2, 2/3 ו‑3/4. הפקד **מרווח** שלמטה קובע
את הרווח בין האזורים; בחירה ב„ללא” מצמידה את החלונות זה לזה.

### פריסות והיסטוריה

**פריסות…** מציג כל מסך עם מצב החיבור, מה יש בו ומתי שימש לאחרונה — כך הגדרות של צג שכבר אין
לך בולטות לעין וניתן למחוק אותן.

כל שמירה משאירה את המצב הקודם ב‑`~/.config/waridake/history/`, עשר הגרסאות האחרונות. אפשר
לשחזר כל אחת מהן מהרשימה, וגם המצב שלפני השחזור נשמר, כך ששום דבר לא הולך לאיבוד.

## הגדרות

הקובץ הוא `~/.config/waridake/layout.json`, ונוצר בהפעלה הראשונה. זהו קובץ רגיל לגמרי —
העורך המובנה הוא נוחות, לא תנאי.

כל אזור נכתב כ**שבר בין 0 ל‑1** של שטח העבודה במסך (מה ששורת התפריטים והדוק משאירים). `x`/`y`
נמדדים מהפינה השמאלית העליונה, `w`/`h` הם רוחב וגובה, ו‑`gap` הוא המרווח בין אזורים בנקודות.

ברירת המחדל היא שתי עמודות שוות:

```json
{
  "gap": 8,
  "zones": [
    { "x": 0,   "y": 0, "w": 0.5, "h": 1 },
    { "x": 0.5, "y": 0, "w": 0.5, "h": 1 }
  ]
}
```

אזורים רשאים לחפוף; הראשון שמכיל את המצביע מנצח.

### פריסות לפי מסך

המסכים נמצאים תחת `displays`, והמפתח הוא ה‑UUID של המסך. העורך הגרפי כותב זאת עבורך. מסכים
בלי רשומה משתמשים ב‑`gap` / `zones` שלמעלה. `name` ו‑`usedAt` הם רישום פנימי — רק היישום כותב
אותם.

```json
{
  "gap": 8,
  "zones": [
    { "x": 0,   "y": 0, "w": 0.5, "h": 1 },
    { "x": 0.5, "y": 0, "w": 0.5, "h": 1 }
  ],
  "displays": {
    "37D8832A-2D66-02CA-B9F7-8F30A301B230": {
      "name": "Studio Display",
      "usedAt": "2026-08-13T12:25:00Z",
      "gap": 0,
      "zones": [
        { "x": 0,    "y": 0, "w": 0.25, "h": 1 },
        { "x": 0.25, "y": 0, "w": 0.5,  "h": 1 },
        { "x": 0.75, "y": 0, "w": 0.25, "h": 1 }
      ]
    }
  }
}
```

קבצים ללא `displays` עדיין נטענים וחלים על הכול.

רובן לא נכתבו בידי דוברים ילידיים, ולכן תיקונים הם סוג ה‑pull request המבורך ביותר. הוספת שפה

את הצד הימני של כל שורה ולבנות מחדש. מה שלא יתורגם יחזור לאנגלית.

## איך זה עובד

- מנטר אירועים גלובלי עוקב אחרי גרירות עם הלחצן השמאלי (בשביל זה נדרשת הרשאת הנגישות)
- בלחיצה, החלון שמתחת למצביע נמצא דרך ממשק הנגישות
- האזורים מופיעים רק אחרי ש**החלון עצמו זז**, כך שסימון טקסט או גרירת קובץ בתוך חלון לא מפעילים
  דבר
- שחרור Shift מסתיר את האזורים והגרירה נמשכת כרגיל

## פתרון תקלות

- **לא מופיעים אזורים** — יש לבדוק את הרשאת הנגישות; כל עוד היא חסרה, בתפריט מופיע פריט עם ⚠️
