一款只做屏幕分割的 macOS 窗口贴靠工具。

*Waridake*(割り竹)意为“劈开的竹子”——干净利落的一刀,仅此而已。

**它能做什么:**

1. 为每台显示器设定区域
2. **拖动窗口时按住 Shift**,区域随即显现
3. 在某个区域上松手,窗口就嵌进去

没有快捷键矩阵,没有窗口历史,没有订阅。它只待在菜单栏里。

> 以英文版 [README.md](../README.md) 为准。若本译文落后,以英文版为准。

## 安装

需要 Xcode 命令行工具(`xcode-select --install`)。

```bash
git clone https://github.com/omikuji/waridake.git
cd waridake
make install   # → /Applications/Waridake.app
```

首次启动时 macOS 会索取辅助功能权限。请在**系统设置 → 隐私与安全性 → 辅助功能**中
打开 Waridake。应用运行期间授予即可,它一秒内就会察觉,无需重启。

想登录时自动启动,请在系统设置 → 通用 → 登录项中添加 Waridake.app。

### 关于重新编译

默认采用临时(ad-hoc)签名,因此**每次重新编译签名都会变,macOS 会悄悄收回权限**——
勾选框看着还是开的,却什么都不管用。可以从辅助功能列表里删掉 Waridake 再重新添加;
也可以一劳永逸:在“钥匙串访问”中创建自签名的代码签名证书(证书助理 → 创建证书,
类型选“代码签名”),然后用它编译:

```bash
make install SIGN_IDENTITY="Waridake Dev"
```

## 使用方法

所有功能都在菜单栏图标下。

| 菜单项 | 作用 |
| --- | --- |
| **整理已打开的窗口** | 把每个打开的窗口放进离它最近的区域。窗口跑偏时用来收拾 |
| **编辑布局…** | 下面介绍的图形编辑器 |
| **布局列表…** | 各显示器的布局及最近使用时间,以及编辑历史 |
| **以 JSON 编辑…** | 在朴素的编辑窗口里改配置文件 |
| **重新载入布局** | 在别处改过文件后重新读取 |

布局按**每台显示器**分别保存,因为屏幕的形状和大小各不相同,同一种分法不可能都合适。
显示器以 UUID 辨认,所以拔插和重启之后设置依然在。

### 图形编辑器

选择**编辑布局…**会在所有已连接的显示器上同时打开编辑器。各屏分别编排,在任意一屏上
按“存储”即可全部保存。尺寸以百分比显示,不必去读小数。

| 操作 | 作用 |
| --- | --- |
| **右键点按区域** | 分成 2 份或 3 份、均分、在屏幕上居中 |
| **分界线上的“合并”按钮** | 把这两个区域并成一个。只在两者能拼成矩形处出现 |
| 拖动分界线 | 移动它。两侧的区域会一起伸缩,不会留出空隙 |
| **⌥ 拖动**分界线 | 同时移动以屏幕中线对称的另一条分界线——用来把中间区域均匀撑宽 |
| 双击区域 | 在该处沿较长的一边切开(⌥ 反转方向) |
| `V` `H` `⌫` `⌘Z` `R` | 分割、反向分割、与相邻区域合并、撤销、恢复初始 |
| `return` / `esc` | 存储并关闭 / 放弃 |

“均分此列”会把同一列里上下排列的区域拉齐(比如左边缘的四等分);对行则是拉齐宽度。
屏幕上别处同样大小的区域不受影响。

“在屏幕上居中”在不改变大小的前提下,把区域挪到相对中线对称的位置。紧贴屏幕边缘的
区域没法这样移动,该菜单项会保持不可用。

分界线会吸附到其他区域的边,以及 1/4、1/3、1/2、2/3 和 3/4。底部的**间隙**用来设定
区域之间的留白;选“无”就让窗口彼此紧贴。

### 布局列表与历史

**布局列表…**会列出每台显示器的连接状态、内容和最近使用时间,已经不用的显示器设置
一眼就能看出来,并可删除。

每次存储都会把上一个状态留在 `~/.config/waridake/history/`,保留最近 10 个版本。
随时可以从列表里恢复,而恢复前的状态同样会被存档,所以不会丢。

## 配置

配置文件是 `~/.config/waridake/layout.json`,首次启动时生成。它就是一个普通文件——
内置编辑器只是方便,并非必需。

每个区域都写成屏幕可用区域(去掉菜单栏和程序坞之后)的 **0 到 1 之间的比例**。
`x`/`y` 从左上角起算,`w`/`h` 是宽和高,`gap` 是区域之间的间隙(点)。

默认是等宽两栏:

```json
{
  "gap": 8,
  "zones": [
    { "x": 0,   "y": 0, "w": 0.5, "h": 1 },
    { "x": 0.5, "y": 0, "w": 0.5, "h": 1 }
  ]
}
```

区域可以重叠;先包含指针的那个胜出。

### 各显示器的布局

显示器写在 `displays` 下,以显示器 UUID 为键。图形编辑器会替你写好。没有条目的显示器
使用最外层的 `gap` / `zones`。`name` 和 `usedAt` 只是记录,由应用写入。

```json
{
  "gap": 8,
  "zones": [
    { "x": 0,   "y": 0, "w": 0.5, "h": 1 },
    { "x": 0.5, "y": 0, "w": 0.5, "h": 1 }
  ],
  "displays": {
    "37D8832A-2D66-02CA-B9F7-8F30A301B230": {
      "name": "Studio Display",
      "usedAt": "2026-08-13T12:25:00Z",
      "gap": 0,
      "zones": [
        { "x": 0,    "y": 0, "w": 0.25, "h": 1 },
        { "x": 0.25, "y": 0, "w": 0.5,  "h": 1 },
        { "x": 0.75, "y": 0, "w": 0.25, "h": 1 }
      ]
    }
  }
}
```

没有 `displays` 的旧配置文件照样能读,并对所有屏幕生效。

## 语言

26 种语言,依据 macOS 的语言设置自动选择——无需配置。

其中大多数并非母语者所写,因此纠正译文是最受欢迎的一类 pull request。添加语言只需把
`Resources/en.lproj/Localizable.strings` 复制到 `Resources/<语言>.lproj/`,翻译每行
右侧,再重新编译。未翻译的条目会回退到英文。

## 工作原理

- 全局事件监视器盯着左键拖动(这正是需要辅助功能权限的原因)
- 按下时,通过辅助功能 API 找出指针下的窗口
- 只有在**窗口本身动了之后**才显示区域,因此在窗口里选文字或拖文件都不会触发
- 松开 Shift 后区域消失,拖动照常进行

## 疑难排解

- **不出现区域** —— 检查辅助功能权限;权限缺失时菜单里会有一个 ⚠️ 项
- **重新编译后就不灵了** —— 见上文“关于重新编译”
- **某个应用不肯就位** —— 它拒绝了调整大小。有最小窗口尺寸的应用(包括部分 Electron
  应用)会比区域更大
