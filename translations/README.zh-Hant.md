一款只做螢幕分割的 macOS 視窗貼齊工具。

*Waridake*(割り竹)意為「劈開的竹子」——乾淨俐落的一刀,僅此而已。

**它能做什麼:**

1. 為每部顯示器設定區域
2. **拖移視窗時按住 Shift**,區域隨即顯現
3. 在某個區域上放開,視窗就嵌進去

沒有快速鍵矩陣,沒有視窗歷史,沒有訂閱。它只待在選單列裡。

> 以英文版 [README.md](../README.md) 為準。若本譯文落後,以英文版為準。

## 安裝

需要 Xcode 命令列工具(`xcode-select --install`)。

```bash
git clone https://github.com/omikuji/waridake.git
cd waridake
make install   # → /Applications/Waridake.app
```

首次啟動時 macOS 會要求輔助使用權限。請在**系統設定 → 隱私權與安全性 → 輔助使用**中
打開 Waridake。App 執行期間授予即可,它一秒內就會察覺,不必重新啟動。

想在登入時自動啟動,請在系統設定 → 一般 → 登入項目中加入 Waridake.app。

### 關於重新編譯

預設採用臨時(ad-hoc)簽署,因此**每次重新編譯簽署都會變,macOS 會悄悄收回權限**——
勾選框看起來還是開著,卻什麼都不管用。可以從輔助使用列表中移除 Waridake 再重新加入;
也可以一勞永逸:在「鑰匙圈存取」中建立自我簽署的程式碼簽署憑證(憑證輔助程式 →
建立憑證,類型選「程式碼簽署」),然後用它編譯:

```bash
make install SIGN_IDENTITY="Waridake Dev"
```

## 使用方式

所有功能都在選單列圖像下。

| 選單項目 | 作用 |
| --- | --- |
| **整理已開啟的視窗** | 把每個開著的視窗放進離它最近的區域。視窗跑掉時用來收拾 |
| **編輯佈局…** | 下面介紹的圖形編輯器 |
| **佈局列表…** | 各顯示器的佈局與最近使用時間,以及編輯紀錄 |
| **以 JSON 編輯…** | 在樸素的編輯視窗裡改設定檔 |
| **重新載入佈局** | 在別處改過檔案後重新讀取 |

佈局按**每部顯示器**分別儲存,因為螢幕的形狀與大小各不相同,同一種分法不可能都合適。
顯示器以 UUID 辨認,所以拔插與重新開機之後設定依然在。

### 圖形編輯器

選擇**編輯佈局…**會在所有已連接的顯示器上同時打開編輯器。各螢幕分別編排,在任一螢幕上
按「儲存」即可全部存起來。尺寸以百分比顯示,不必去讀小數。

| 操作 | 作用 |
| --- | --- |
| **在區域上按右鍵** | 分成 2 份或 3 份、均分、在螢幕上置中 |
| **分界線上的「合併」按鈕** | 把這兩個區域併成一個。只在兩者能拼成矩形處出現 |
| 拖移分界線 | 移動它。兩側的區域會一起伸縮,不會留下空隙 |
| **⌥ 拖移**分界線 | 同時移動以螢幕中線對稱的另一條分界線——用來把中間區域均勻撐寬 |
| 點兩下區域 | 在該處沿較長的一邊切開(⌥ 反轉方向) |
| `V` `H` `⌫` `⌘Z` `R` | 分割、反向分割、與相鄰區域合併、還原、回到初始 |
| `return` / `esc` | 儲存並關閉 / 放棄 |

「均分此欄」會把同一欄裡上下排列的區域拉齊(例如左邊緣的四等分);對列則是拉齊寬度。
螢幕上別處同樣大小的區域不受影響。

「在螢幕上置中」在不改變大小的前提下,把區域挪到相對中線對稱的位置。緊貼螢幕邊緣的
區域沒辦法這樣移動,該選單項目會保持無法選取。

分界線會吸附到其他區域的邊,以及 1/4、1/3、1/2、2/3 和 3/4。底部的**間距**用來設定
區域之間的留白;選「無」就讓視窗彼此緊貼。

### 佈局列表與紀錄

**佈局列表…**會列出每部顯示器的連接狀態、內容與最近使用時間,已經不用的顯示器設定
一眼就看得出來,並可刪除。

每次儲存都會把上一個狀態留在 `~/.config/waridake/history/`,保留最近 10 個版本。
隨時可以從列表回復,而回復前的狀態同樣會被封存,所以不會不見。

## 設定

設定檔是 `~/.config/waridake/layout.json`,首次啟動時產生。它就是一個普通檔案——
內建編輯器只是方便,並非必要。

每個區域都寫成螢幕可用範圍(扣掉選單列與 Dock 之後)的 **0 到 1 之間的比例**。
`x`/`y` 從左上角起算,`w`/`h` 是寬與高,`gap` 是區域之間的間距(點)。

預設是等寬兩欄:

```json
{
  "gap": 8,
  "zones": [
    { "x": 0,   "y": 0, "w": 0.5, "h": 1 },
    { "x": 0.5, "y": 0, "w": 0.5, "h": 1 }
  ]
}
```

區域可以重疊;先包含指標的那個勝出。

### 各顯示器的佈局

顯示器寫在 `displays` 底下,以顯示器 UUID 為鍵。圖形編輯器會替你寫好。沒有項目的
顯示器使用最外層的 `gap` / `zones`。`name` 與 `usedAt` 只是紀錄,由 App 寫入。

```json
{
  "gap": 8,
  "zones": [
    { "x": 0,   "y": 0, "w": 0.5, "h": 1 },
    { "x": 0.5, "y": 0, "w": 0.5, "h": 1 }
  ],
  "displays": {
    "37D8832A-2D66-02CA-B9F7-8F30A301B230": {
      "name": "Studio Display",
      "usedAt": "2026-08-13T12:25:00Z",
      "gap": 0,
      "zones": [
        { "x": 0,    "y": 0, "w": 0.25, "h": 1 },
        { "x": 0.25, "y": 0, "w": 0.5,  "h": 1 },
        { "x": 0.75, "y": 0, "w": 0.25, "h": 1 }
      ]
    }
  }
}
```

沒有 `displays` 的舊設定檔照樣讀得進來,並對所有螢幕生效。

## 語言

26 種語言,依據 macOS 的語言設定自動選擇——不必設定。

其中大多數並非母語者所寫,因此修正譯文是最受歡迎的一類 pull request。加入語言只需把
`Resources/en.lproj/Localizable.strings` 複製到 `Resources/<語言>.lproj/`,翻譯每行
右側,再重新編譯。未翻譯的項目會退回英文。

## 運作方式

- 全域事件監視器盯著左鍵拖移(這正是需要輔助使用權限的原因)
- 按下時,透過輔助使用 API 找出指標下的視窗
- 只有在**視窗本身動了之後**才顯示區域,因此在視窗裡選字或拖檔案都不會觸發
- 放開 Shift 後區域消失,拖移照常進行

## 疑難排解

- **不出現區域** —— 檢查輔助使用權限;權限缺少時選單裡會有一個 ⚠️ 項目
- **重新編譯後就失靈** —— 見上文「關於重新編譯」
- **某個 App 不肯就位** —— 它拒絕了調整大小。有最小視窗尺寸的 App(包括部分 Electron
  App)會比區域更大
